# 技術構成：カメラと画面（Unity）のつながり

「リアルおままごと調理システム」のうち、**カメラ（Python）・サーバー（Rust）・画面（Unity）** がどうつながっているかを、1 つにまとめた文書。
くわしい経緯は `docs/作業記録_Unity.md`、Unity の動かし方は `unity/README.md`、決まりごとは `docs/要件定義書_v1.md`。

- 作成：2026-11-24（Unity を作る PC の Claude）
- **しくみが変わったら、この文書も直す**（作業記録を書くときに、いっしょに見直す）

---

## 1. ひとことで

**カメラとセンサーが「何が起きたか」を見て、サーバーが判断し、Unity は届いたとおりに演出を出すだけ。**

- 判断（切った・入れた・何グラム・採点）は **サーバー** がする。**画面は判断しない**
- カメラ・センサーとサーバー、サーバーと画面は、**JSON のイベント** でやり取りする

## 2. 全体の図

```
 おもちゃのキッチン
 ┌──────────────────────┐
 │ 包丁・野菜・まな板      │── Web カメラ（3 台の予定。今は Brio 100 × 2）
 │ 電子レンジ（黒いテープ）│        │ 映像
 │ 塩・こしょう・つまみ    │        ▼
 └──────────────────────┘   ┌──────────────────────┐
        │ 振る・回す            │ Python（camera/）      │
        ▼                      │  学習モデルで物を見つける │
 ┌────────────────┐           │  切った・入れたを決める   │
 │ M5StickS3（device/）│        └──────────┬───────────┘
 │  振り・つまみ        │                   │ WebSocket  ws://<PC>:9000/camera
 └──────┬─────────┘                   ▼
        │ BLE              ┌────────────────────────────┐
        └────────────────▶│ サーバー（server/、Rust）       │
                           │  グラム・火の強さ・ピース数を管理 │
                           │  画面にイベントを配る            │
                           └──────────────┬─────────────┘
                                          │ WebSocket  ws://<PC>:9000/screen
                                          ▼
                           ┌────────────────────────────┐
                           │ 画面（unity/、Unity 6.3・URP） │
                           │  横のモニター：キッチン          │
                           │  縦のモニター：お客さん（まだ）   │
```

展示では、これを全部 **1 台の PC（Windows・NVIDIA の GPU）** で動かす。開発中は別の PC に分かれることもある（そのときは `localhost` の代わりに、その PC の IP にする）。

## 4. 画面（Unity）に届くイベント

サーバーから `ws://<PC>:9000/screen` に、JSON が 1 つずつ届く（要件定義書 6.4）。共通で `device`・`ts`（時刻）・`seq`（番号）が付く。

| event | 中身の例 | Unity の演出 | Unity のスクリプト |
| --- | --- | --- | --- |
| `position` | 包丁の刃先と柄・野菜の位置（まな板の上で 0〜1） | 包丁・にんじんがなめらかに動く | `KnifeView`・`CarrotView` |
| `swing` | — | 包丁をトンと振り下ろす | `KnifeView` |
| `cut` | `count`：今のピースの数 | にんじんが一気に輪切りになる | `CarrotView` |
| `add` | `zone`：pan / plate、`count` | ピースがフライパン・皿へ飛ぶ | `CarrotView`・`PanView` |
| `season` | `item`：salt / pepper、グラム | 入れ物が飛んで振る・粒が落ちる | `ShakerView` |
| `fire` | `level`：0〜3 | 青い炎・つまみが回る・焼けて色が変わる | `GasBurnerView`・`PanView` |
| `serve` | `score`・`comment` | フライパンの中身が皿へ | `PanView` |
| `reset` | — | 全部はじめに戻る | 全部 |
| `status` | デバイスのつながり・電池 | （まだ使っていない） | — |
| **`door`（仮）** | `open`・`angle`（度） | 電子レンジの扉がその角度まで開く | `MicrowaveDoorView` |

- `door` は 2026-11-17 に**試しで足した**もので、**要件定義書 6.4 にもサーバーにもまだない**（8 章）
- Unity から送るのは 2 つだけ：つながったときの `{"event":"hello"}`、リセットするときの `{"event":"reset"}`

## 5. Unity の中のしくみ

```
サーバー ──WebSocket──▶ ServerConnection ──▶ EventRouter ──▶ 演出のスクリプト（○○View）
                          （つなぐ・つなぎ直す）  （種類ごとに振り分け）   （動かすだけ）
キーボード（KeyboardEventSender）──┘                 ▲
デモ（DemoPlayer）─────────────────────────────┘
```

- **`ServerConnection`**：`ws://localhost:9000/screen` につなぐ。切れたら自動でつなぎ直す（1〜10 秒おき）
- **`EventRouter`**：届いた JSON を種類ごとに振り分ける。同じ `seq` 以下は捨てる。サーバー・キー・デモのどこから来ても、ここを通る
- **演出のスクリプト**：`EventRouter` の `OnCut` などに登録して待つ。**判断はしない**
- **サーバーなしで試す**：キー（K C A S P 0〜3 Enter **M** R D）、またはサーバーがないと 3 秒後にデモが流れる
- **キッチンの形**：全部コードで作る（`Assets/Scripts/Editor/Kitchen*Builder.cs`）。メニュー「Omamagoto → キッチンを作り直す」。寸法は現実の mm で書く
- **テスト**：EditMode 30 個・PlayMode 48 個（`Window → General → Test Runner`）

## 6. カメラ側（Python）

### 6.1 ファイル

| ファイル | すること | 作った人 |
| --- | --- | --- |
| `camera/main.py` | 本番のカメラのプログラム。包丁・野菜を見つけて、切った・入れたを決めてサーバーに送る | カメラ担当 |
| `camera/detect.py` | 学習モデル（ultralytics）と手の検出（MediaPipe） | カメラ担当 |
| `camera/two_cameras.py` | **確かめる道具**：カメラ 2 台の映像を並べ、台のどこが見えているかを真上の図で色分けする | Unity 担当 |
| `camera/door_watch.py` | **試しの道具**：電子レンジの扉の角度を測って Unity に送る（にんじんを入れたかも見られる） | Unity 担当 |
| `camera/onnx_detect.py` | 学習モデルを **GPU（DirectML）** で動かす部品。`detect.py` と同じ形の結果を返す | Unity 担当 |
| `camera/config/` | 位置合わせの結果（台の寸法・扉の蝶番の位置・閉めたときの映像） | — |
| `camera/captures/` | 確認用に保存した映像（git に入れない） | — |

### 6.2 電子レンジの扉の角度（`door_watch.py`）

```
カメラ 1（電子レンジを上から）
   │ 映像（1 秒に 30 枚）
   ▼
① 黒いテープを探す ─── 扉の上のふちに貼った黒いテープ。台（木）の上でよく目立つ
② 蝶番から角度を変えて線を引き、新しく黒くなった所がいちばん多い向き ＝ 扉の向き
③ 閉めた向きを 0 度、いっぱいに開けた向きを 90 度として、角度に直す（120% まで見る）
   │ {"event":"door","open":true,"angle":45.0}
   ▼
Unity の MicrowaveDoorView が、その角度まで扉を開く
```

- **覚えること**：扉を閉めて `c`（テープから蝶番と扉の先を自動で決める）→ いっぱいに開けて `o`（開く向き）。**カメラを動かしたら、扉を閉めて `c` だけ**
- **速さ**：1 回の判定は約 30 ms（カメラの速さいっぱい）。学習モデルは**別のスレッド**で動かすので、扉の判定は止まらない
- **今は試し用**：本物のサーバーの代わりに、この道具が `ws://localhost:9000/screen` を開いて Unity に直接送る。**Rust のサーバーと同時には動かせない**（同じ 9000 番を使うため）

### 6.3 学習モデル

- 形式：YOLOv8n を ONNX に書き出したもの（入力 640 × 640）
- `models/best.onnx`：チームのモデル（包丁・野菜）。**変えない**
- `models/test_green.onnx`：テストで作った（ピーマン・ブロッコリー）。`test_pepper.onnx` はピーマンだけの古い版
- 速さ（この PC、i7-13620H・GTX 1650）：CPU で 46〜66 ms、**GPU（DirectML）で 23 ms**

## 8. まだ決まっていないこと・気をつけること

- **電子レンジの扉を何で見るか**：要件定義書 5.5 ではリードスイッチ（目標）。今はカメラ＋黒いテープで試している。決めたら、6.4 に `door` を足して、サーバーで画面に配る（サーバー担当）
- **カメラの台数と置き方**：今は 2 台。予定は 3 台（左・センター・右）。Brio 100 は画角がせまいので、広角のカメラ（Anker C200 など）も考える
- **実物のキッチン台の寸法**：奥行き 340 mm（設計図は 550 mm）。置き場の位置はまだ測っていない（`camera/config/table_layout.json` は仮）
- **Windows で気をつけること**
  - カメラは、**大きさを決めてから MJPG** にする（逆だと 1 秒に 5 枚しか来ない）。`camera/main.py` にも同じことがある
  - `cv2.imwrite` は**日本語のパスに書けない**（`train/auto_label.py` も同じ）。クラスの名前は今は英語にしている
  - 学校のネットワークでは SSL のエラーが出る → Git は `http.sslBackend schannel`、Python は `truststore`、uv は `UV_NATIVE_TLS=true`
- **onnxruntime を DirectML 版に入れ替えた**ので、ultralytics が自分で CPU 版を入れ直そうとすることがある。そのときは `$env:YOLO_AUTOINSTALL='False'` にする
