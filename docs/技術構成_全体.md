# 技術構成：全体

「リアルおままごと調理システム」全体が、どんな部品でできていて、どうつながっているかを、ざっくりまとめた文書。
細かいことは、それぞれの README と `docs/要件定義書_v1.md` を見る。カメラと Unity のつながりは `docs/技術構成_カメラと画面.md` にくわしく書いてある。

- 作成：2026-11-24（Unity を作る PC の Claude）。`docs/要件定義書_v1.md`（3 章・10 章）と各フォルダーの README をもとにまとめた
- **しくみが変わったら、この文書も直す**

---

## 1. どんな作品か

机の上の**おもちゃのキッチン**で料理のまねをすると、カメラとセンサーが動きを読み、モニターの中では**本物の料理**をしているように見える。
作った料理は、**画像生成 AI** で本物の料理の写真になり、画面の中の**クマのお客さん**が食べて点数を付ける。HAL の HEW（2027 年 3 月）に出す。

## 3. 部品ごとのまとめ

| 部品 | フォルダー | 言葉・道具 | すること | 今どこまで（2026-11-24） |
| --- | --- | --- | --- | --- |
| センサー | `device/` | C++（PlatformIO）・M5StickS3 | 塩・こしょうの「振り」、コンロのつまみの「回転」を検知して BLE で送る。全部同じファームで、役割はサーバーが決める | 動く。提供カウンターのスイッチはまだ |
| カメラ | `camera/` | Python・OpenCV・YOLO・MediaPipe | 包丁・野菜・手を見つけて、位置・切った・入れたを送る | 1 台で動く。3 台の統合はまだ。電子レンジの扉の角度（試し）はできた |
| 学習 | `train/`・`tools/capture.py`・`models/` | Python・ultralytics（YOLOv8） | おもちゃの写真を撮る → 自動で枠を付ける → 学習 → `models/*.onnx` | 包丁・野菜のモデルあり。ピーマン・ブロッコリーで試した |
| サーバー | `server/` | Rust（tokio・btleplug・axum） | 全部をつなぐ。振り → グラム、つまみ → 火の強さ、カメラのイベントを画面へ、リセット | 動く。提供・採点・焼き加減はまだ |
| 画面 | `unity/` | Unity 6.3 LTS・URP・C# | イベントを受けて 3D の演出を出す。判断はしない | キッチンの画面はひと通り動く（実物の台 900 × 340 mm・コンロ 1 口に合わせた）。カメラで見た電子レンジの扉・ピーマン・ブロッコリーも映る（試し）。お客さんの画面はまだ |
| 画面の見本 | `screen/index.html` | three.js | 動きの見本（本番では使わない）。キッチン・お客さんの両方の試作がある | 動く |
| 料理の写真 | `screen/dish_server.py` | Python（標準ライブラリだけ）・OpenAI | 皿の写真と料理の状態（焼き加減・塩・こしょう）から、本物の料理の写真を作らせる。API キーはここだけが持つ | three.js の試作では動く。Unity とのつなぎはまだ |
| キッチン台 | `docs/キッチン設計書.md`・`tools/kitchen_plan.py` | 木（シナ合板） | モニターを背板にはめ、カメラをアームで付ける | 作っている途中 |

## 4. つながり方（データの流れ）

| どこから → どこへ | 道 | 中身の例 |
| --- | --- | --- |
| センサー → サーバー | **BLE**（1 行 1 JSON） | `{"event":"shake","intensity":0.6}`・`{"event":"knob","level":2}` |
| カメラ → サーバー | **WebSocket** `ws://<PC>:9000/camera` | `{"event":"cut","item":"carrot","count":2}` |
| サーバー → 画面 | **WebSocket** `ws://<PC>:9000/screen` | `{"event":"fire","level":2}`・`{"event":"season","item":"salt","total_g":3.2}` |
| 画面 → サーバー | WebSocket（同じ道） | `{"event":"hello"}`・`{"event":"reset"}` |
| 料理の写真 | HTTP `http://localhost:9001/dish` | 送る：指示の文と皿の写真 → 返る：料理の写真 |

- どのイベントにも、共通で `device`（送ったもの）・`ts`（時刻）・`seq`（番号）が付く
- 形は要件定義書 6 章で決めている。**変えるときは、要件定義書を直してから**

## 5. 使っている主な技術

| 分野 | 技術 | ひとこと |
| --- | --- | --- |
| マイコン | M5StickS3（ESP32-S3）・PlatformIO・NimBLE・ArduinoJson | 小さくて電池入り。容器やつまみに入る |
| 画像認識 | YOLOv8n（物を見つける）・MediaPipe（手を見つける）・OpenCV | おもちゃの写真で自分たちで学習する |
| 推論を速く | ONNX・onnxruntime（DirectML で GPU） | CUDA を入れなくても GPU が使える |
| サーバー | Rust・tokio（同時にたくさん待つ）・btleplug（BLE）・axum（WebSocket） | 長い時間止まらずに動かすため |
| 3D の画面 | Unity 6.3 LTS・URP・Newtonsoft Json | 本物らしい光と素材（PBR・HDRI・SSAO） |
| 背景（目標） | 3DGS（XGRIDS で撮影）・UnityGaussianSplatting | 本物の部屋を 3D で。重ければ静止画・動画にする |
| 料理の写真 | OpenAI GPT Image（`gpt-image-2`） | 1 枚 約 24 秒。待つ間はお客さんの画面で演出する |
| 素材 | Poly Haven・ambientCG（CC0） | 出どころは `unity/Assets/CREDITS.md` |
| 開発 | Git・Git LFS（大きいファイル）・Claude Code（MCP で Unity・Blender を操作） | |

## 6. 機材（展示）

- PC：1 台（Windows・NVIDIA の GPU）
- モニター：横 27 インチ（キッチン。キッチン台の背板にはめる）、縦（お客さん）。目標で廊下にもう 1 台
- カメラ：3 台の予定（中央 Anker C200、左右 Logicool Brio 100）。今は Brio 100 × 2 で試している
- M5StickS3：4〜6 台（塩・こしょう・つまみ・提供カウンター）
- おもちゃ：100 円ショップの野菜・包丁・まな板・フライパン・調味料の容器
