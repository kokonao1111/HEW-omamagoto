# 進め方：BLE 通信と Rust サーバー

センサーデバイス（M5StickS3）から展示用 PC の Rust サーバーまでを BLE でつなぎ、
「振る・回す → サーバーで鍋の状態が変わる」までを動かすための作業計画。
進んだら「状態」と「やったこと」を書き換える。テストの結果は `docs/テスト記録.md` に書く。

## 決めたこと（2026-10-13）

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 通信 | BLE。デバイスが周辺機器、展示用 PC が親 | 電池の持ち。会場の Wi-Fi・テザリングに依存しない |
| 受け側 | 展示用 PC の Bluetooth で直接受ける | 展示用 PC は 30 万円程度の高性能機（Bluetooth 5）。ESP32 を USB 受信機にする案は、PC で安定しなかったときの予備 |
| サーバー | Rust のまま | 要件定義書 3 章のとおり |
| 取り決め | 要件定義書 6.6（名前・UUID・JSON の分け方） | |

## 全体の形

```
M5StickS3（塩・こしょう・フライパン・つまみ）──BLE──┐
ESP32（電子レンジ）─────────────────────BLE──┤
                                                      ▼
カメラ（Python）──WebSocket（PC内）──▶  Rust サーバー  ──WebSocket（PC内）──▶ Unity
```

サーバーの中は「入り口（BLE・WebSocket）」と「本体（鍋の状態・工程・採点）」に分け、入り口から本体へはチャンネルでイベントを渡す。
非同期（tokio）を使うのは入り口だけにして、本体は普通の関数で書く。

## 段階

1 段階ずつ PR にして `main` に入れてから次を始める。

### ① デバイスの BLE 送信（`feature/ble-device`）

- 状態：**完了（2026-10-13）**
- 作るもの
  - `device/`：NimBLE-Arduino で周辺機器になり、6.6 のとおりに JSON を通知する。USB シリアルへの出力も残す
  - 画面に BLE の状態（接続中・待機中）を出す
  - `tools/ble_monitor.py`：Mac・Windows で BLE のデバイスを探してつなぎ、届いた JSON を表示する確認用ツール（Python・bleak）。サーバーを作る前に、デバイス側だけを確かめるのに使う
- 終わりの条件
  - `tools/ble_monitor.py` で、振る・回すと JSON が届く
  - 本体のリセット・Mac 側の切断のあと、自動でつながり直す
- テスト：Mac 上のテスト（`device/host_test/run.sh`）、実機で `ble_monitor.py`
- やったこと（2026-10-13）
  - デバイスの BLE 送信と `tools/ble_monitor.py` を作り、Mac で受け取れた。振り 10 回 × 2 で 10 件ずつ、取りこぼし 0 件（`docs/テスト記録.md`）
  - 本体のリセット後、3.7 秒でつながり直した

### ② Rust で BLE を受ける（`feature/server-ble`）

- 状態：**作業中**
- 作るもの
  - `server/`：Cargo プロジェクト。btleplug で 6.6 のサービスを持つデバイスを探して全台につなぎ、通知を改行までつなげて JSON にして表示する。切れたらつなぎ直す
- 終わりの条件：Mac で `cargo run` して、振る・回すと JSON がターミナルに出る。切断・再接続も確かめる
- やったこと（2026-10-13）
  - `server/` を作り、Mac で受け取れた（`knob`・`battery`）。`cargo test` 5 件 OK
  - サーバーの再起動から再接続までが 11〜12 秒かかることがあったので、接続のタイムアウトを短くし、Ctrl+C では切断してから終わるようにした。6 回とも 2.4〜2.6 秒
  - 残り：Rust サーバーで振りの回数と本体リセット後の再接続を確かめる

### ③ サーバーの本体（`feature/server-core`）

- 状態：未着手
- 作るもの
  - 6.2 のイベントの型（`enum`）、MAC アドレス → 役割の設定ファイル（6.5、TOML）
  - 本体：連番の重複を捨てる、振り → グラム、つまみ → 火の強さ。受信したものと出したものをファイルに記録する
  - Unity・カメラとの WebSocket は ③ のあとの段階で作る
- 終わりの条件：塩を振ると `season`、つまみを回すと `fire` のイベントがログに出る。本体の処理は Mac 上のテスト（`cargo test`）で確かめる
