# サーバー（Rust）

センサーデバイスと BLE で、カメラ（Python）と画面（Unity）と WebSocket でつながり、届いたイベントで鍋の状態を変えて、画面にイベントを送るサーバー。要件定義書の 3 章・5.9・6.3〜6.6 に対応する。
今あるのは調味料（振り → グラム）、火の強さ（つまみ → 段階）、カメラの位置・切った・入れた・振り下ろしを画面に流すこと、リセット。焼き加減・工程・採点・提供は次の段階で足す（`docs/進め方_BLEとサーバー.md`）。

## 動かす

Rust が入っていなければ、先に入れる（https://rustup.rs の 1 行のコマンド）。

```sh
cd server
cargo run                           # config.toml を読み、近くの omamagoto- のデバイスを全部探してつなぐ。止めるのは Ctrl+C
cargo run -- 別の設定.toml          # 設定ファイルを変える
cargo run -- --no-ble               # BLE を使わない（デバイスの無い PC で、カメラと画面だけ試す）
cargo test                          # Mac 上のテスト（実機は要らない）
```

- Bluetooth が使えないときは「BLE が止まった。デバイスなしで続ける」と出て、カメラと画面だけで動き続ける

- macOS では、初回にターミナルへの Bluetooth の使用許可を求められる
- Ctrl+C で止めると、つないでいるデバイスを切ってから終わる。強制終了してもデバイスの再起動は要らない

## 画面とカメラとのつなぎ方（WebSocket）

`config.toml` の `[ws]` の `listen` で待つ（今は `0.0.0.0:9000`。別の PC からもつなげる）。

| つなぐ所 | 相手 | やり取り |
| --- | --- | --- |
| `ws://<PC>:9000/screen` | 画面（Unity・`screen/index.html`） | サーバーが出したイベント（要件定義書 6.4）を、つながっている全部の画面に送る |
| `ws://<PC>:9000/camera` | カメラ（`camera/main.py`） | 6.3 の JSON を受け取る。パスを付けずに `ws://<PC>:9000` でつないでもカメラとして扱う |

画面に送るもの（共通ヘッダ `device`・`ts`・`seq` が付く。`seq` はサーバーを起動するたびに 1 から）

| event | いつ |
| --- | --- |
| `position` | カメラから位置が届いたとき（そのまま流す。`cam` は外す） |
| `swing` | カメラが振り下ろしを見たとき |
| `cut` | カメラが「切った」を確定したとき（`count` は今のピース数） |
| `add` | カメラが「フライパン・皿に入った」を確定したとき（`count` は増えた数） |
| `season` | 塩・こしょうを振ったとき |
| `fire` | つまみの段階が変わったとき。画面がつながったとき（`hello`）とリセットのあとにも、火がついていれば今の段階を送る |
| `reset` | リセットしたとき |

画面から受け取るもの

| event | サーバーがすること |
| --- | --- |
| `hello` | 画面がつながった。今の状態（火）を送る |
| `reset` | 鍋の状態（調味料・ピース数・フライパンの中身）を空にして、全部の画面に `reset` を送る。火はつまみの実際の位置なので戻さない |

まだ無いもの：`serve`（提供と採点）、`status`（デバイスの接続とバッテリー）、焼き加減、無操作の自動リセット

## 設定（`config.toml`、要件定義書 6.5）

- `[roles]`：デバイスの MAC アドレス → 役割（`salt`・`pepper`・`pan`・`knob`・`range`）。MAC アドレスはデバイスの画面の 1 行目に出ている。設定に無いデバイスがつながると、サーバーが MAC アドレスを表示する
- `[season]`：`grams_per_shake` は強さ 1 で 1 回振ったときのグラム数。強さが小さければその分少なくなる
- 書き換えたらサーバーを再起動する

## ログ（`logs/`、git には入れない）

起動ごとに `日時.jsonl` を作り、受け取ったもの（`in`）・出したもの（`out`）・接続と切断（`note`）を 1 行 1 JSON で書く。
役割に合わないイベント（塩のデバイスの `knob` など）は表示しないが、ログには残る。

## 作り

入り口（BLE）と本体を分け、入り口から本体へはチャンネルで 1 件ずつ渡す。非同期（tokio）を使うのは入り口と `main.rs` だけにして、本体（`kitchen.rs`）は普通のコードで書き、`cargo test` で確かめる。

重複の判定：同じデバイスから、同じ起動のうちに受け付けた連番以下が来たら捨てる。デバイスが再起動すると `seq` は 1 から、`ts` は 0 から数え直すので、`ts` が戻っていたら再起動とみなして受け付ける。

| ファイル | 役割 |
| --- | --- |
| `src/main.rs` | 入り口（BLE・WebSocket）からのメッセージを 1 件ずつ本体に渡し、出たイベントを表示してログに残し、画面に送る。Ctrl+C で入り口に止めるよう伝える |
| `src/kitchen.rs` | 本体（鍋の状態）。重複を捨てる、役割に合わないイベントを無視する、振り → グラム、つまみ → 火の強さ、カメラのイベント → 画面へ、リセット |
| `src/ws.rs` | WebSocket の入り口。`/screen` の画面に全部のイベントを配り、`/camera` のカメラから受け取る |
| `src/event.rs` | イベントの型（要件定義書 6.2 のデバイスから、6.4 のサーバーから） |
| `src/config.rs` | 設定ファイルを読む |
| `src/event_log.rs` | ログファイルに書く |
| `src/ble.rs` | BLE の入り口。1 秒ごとにデバイスを探し、1 台ずつ専用のタスクでつないで通知を受ける。切れたらタスクが終わり、次に見つけたときにつなぎ直す |
| `src/line_buffer.rs` | 分けて届いた通知を改行までつなげて 1 行にする |

決めている値（`src/ble.rs`）：

| 値 | 理由 |
| --- | --- |
| デバイスを探す間隔 1 秒 | 見つけてからつなぐまでの遅れを小さくする |
| 接続のタイムアウト 3 秒 | 10 秒だと、サーバーを再起動したあとの再接続に 11〜12 秒かかった（2026-10-13 の実測） |
| つながっているかの確認 1 秒ごと | 切断の通知が来ない OS があるため |
