# サーバー（Rust）

センサーデバイスと BLE でつながり、届いたイベントを受け取るサーバー。要件定義書の 3 章・5.9・6.6 に対応する。
今は届いた JSON を表示するだけ。鍋の状態・工程・採点、Unity・カメラとの WebSocket は次の段階で足す（`docs/進め方_BLEとサーバー.md`）。

## 動かす

```sh
cd server
cargo run                           # 近くの omamagoto- のデバイスを全部探してつなぐ。止めるのは Ctrl+C
cargo test                          # Mac 上のテスト（実機は要らない）
```

- macOS では、初回にターミナルへの Bluetooth の使用許可を求められる
- Ctrl+C で止めると、つないでいるデバイスを切ってから終わる。強制終了してもデバイスの再起動は要らない

表示の例：

```
12:40:43.825 omamagoto-5C3C 接続
12:40:44.186 omamagoto-5C3C {"event":"knob","level":0,"angle":22,"device":"AC:27:6E:D3:5C:3C","ts":80091,"seq":38}

```

## 作り

入り口（BLE）と本体を分け、入り口から本体へはチャンネルで 1 件ずつ渡す。非同期（tokio）を使うのは入り口だけにする。

| ファイル | 役割 |
| --- | --- |
| `src/main.rs` | 本体。入り口からのメッセージを 1 件ずつ受ける（今は表示するだけ）。Ctrl+C で入り口に止めるよう伝える |
| `src/ble.rs` | BLE の入り口。1 秒ごとにデバイスを探し、1 台ずつ専用のタスクでつないで通知を受ける。切れたらタスクが終わり、次に見つけたときにつなぎ直す |
| `src/line_buffer.rs` | 分けて届いた通知を改行までつなげて 1 行にする |

決めている値（`src/ble.rs`）：

| 値 | 理由 |
| --- | --- |
| デバイスを探す間隔 1 秒 | 見つけてからつなぐまでの遅れを小さくする |
| 接続のタイムアウト 3 秒 | 10 秒だと、サーバーを再起動したあとの再接続に 11〜12 秒かかった（2026-10-13 の実測） |
| つながっているかの確認 1 秒ごと | 切断の通知が来ない OS があるため |
