# キッチンの画面（three.js の試作）

モニターに映す「本物のキッチン」の画面を、Unity ではなく three.js で作った試作。`index.html` 1 ファイルだけで動く。

サーバーから要件定義書 6.4 のイベントを WebSocket で受けて、演出を出す。画面は判断をしない。

## リアルにするための素材と処理

- `assets/` に、Poly Haven の CC0 素材を置いている（`assets/CREDITS.md`）。本物の部屋の光（HDRI）、壁のタイル、まな板の木、観葉植物・レモン・りんごの 3D
- 仕上げの処理: 物の隙間の影（GTAO）、明るい所のにじみ（ブルーム）、周辺を少し暗く、ギザギザ消し（SMAA）
- 素材が読めないときは、手描きの質感のまま動く
- `?post=0` で仕上げの処理を切る（PC が重いとき）。`?real=0` で素材を使わない
- `?hdrirot=115` で、受け渡し口の向こうに見える向き（度）を変えられる
- 素材は `file://` で開くと読めない。`dish_server.py` から `http://localhost:9001/` で開く

## 開き方

`.venv/bin/python screen/dish_server.py`（試すだけなら `--mock` を付ける）を動かし、Chrome で `http://localhost:9001/` を開く。three.js をインターネットから読み込むので、ネットにつながっている必要がある。

- サーバーにつながっていないときは、デモ（切る → フライパンに入れる → 火をつける → 塩・こしょう → 提供）をくり返し流す
- サーバーにつながると、デモを止めてサーバーのイベントだけで動く
- 展示では Chrome を全画面（F11 かキオスクモード）で開く

## つなぐサーバー

最初は `ws://localhost:9000/screen` につなぐ。変えるときは URL に `?ws=` を付ける。

```
index.html?ws=ws://omamagoto.local:9000/screen
```

つながると `{"device":"screen","event":"hello"}` を 1 回送る。切れたら自動でつなぎ直す。

## 受け取るイベント（要件定義書 6.4）

| event | 画面で起きること |
| --- | --- |
| `position` | 包丁（`tip`・`grip`）と野菜（`x`・`y`・`rot`）を動かす。`visible: false` から 3 秒で消える |
| `swing` | 包丁を振り下ろし、「カッ」と出す |
| `cut` | 野菜が `count` 個に分かれる |
| `add` | まな板のピースが `count` 個、フライパンに飛ぶ |
| `season` | 塩・こしょうの容器がフライパンの上で振られ、合計の g を出す |
| `fire` | つまみが回り、炎が出る（0 = 切 〜 3 = 強）。フライパンの中身が焼けて色が変わる |
| `serve` | 料理が皿に移り、本物の料理の写真に変わる。奥へ出され、お客さんがひと口ずつ食べて、点数とコメントを出す |
| `reset` | 最初の状態に戻す |

## 料理の写真（その場で画像生成）

来場者が作った料理を、そのまま本物らしい料理の写真にして、お客さんに食べさせる。

1. 提供すると、ピースが皿にのった所を、画面の中のカメラで斜め横（手前の右から、見下ろし約 35°）から撮る
2. その画像と、料理の状態（ピースの数・焼き加減・塩とこしょうの量）を書いた指示を、`dish_server.py` に送る
3. `dish_server.py` が画像生成 AI（OpenAI の GPT Image。`--provider gemini` で Gemini にも切り替えられる）に「この皿を、同じ形・同じ数のまま本物の料理写真にして」と頼む
4. 待っている間は「盛り付け中…」と湯気を出す。返ってきた写真が「できあがり！」の札に出る
5. 皿を奥へ出すと、札もクマの横へ動く。クマが食べると、皿のにんじんと札の写真がひと口ずつ欠けていく

指示に入れる料理の状態（人によって違いが出るように、細かく分けて伝える。グラム数もそのまま入れる）

| 項目 | 段階 |
| --- | --- |
| 焼き加減 | 生 → ほぼ生 → 軽く焼けた → ちょうどいい → 焼きすぎ → 真っ黒 の 6 段階 |
| 塩 | なし → ひとつまみ → 少し → しっかり → しょっぱい → 塩の山 の 6 段階（0・0.1・1.5・3・4.5・6 g で区切る） |
| こしょう | なし → 少し → ふった → 多い → 真っ黒 の 5 段階（0・0.1・0.8・1.6・2.5 g で区切る） |

ピースの数・形・皿の上の置き方は、撮った画像のまま残すように頼む。

決まり

- 画像生成を使うのは、サーバー（Rust）から `serve` が来たときだけ。デモでは使わない（お金がかかるので）。操作パネルの「料理の写真を画像生成で作る」をオンにすると、手で試せる
- 20 秒で返ってこない・ネットが切れた・上限に達したときは、`dishes/` に用意した 4 枚の写真から選んで出す（`comment` か `dish` で選ぶ）
- API キーは `dish_server.py` だけが持つ。ページには書かない

動かし方

```
# 本番（OpenAI の API キーを platform.openai.com で作る）
OPENAI_API_KEY=sk-... .venv/bin/python screen/dish_server.py

# 1 枚だけ作って、速さと仕上がりを確かめる（画面なし。皿の画像を渡す）
OPENAI_API_KEY=sk-... .venv/bin/python screen/dish_server.py --test --image 皿.jpg

# API を使わずに流れだけ試す（撮った皿の画像を 3 秒後にそのまま返す）
.venv/bin/python screen/dish_server.py --mock

# Gemini を使うとき
GEMINI_API_KEY=... .venv/bin/python screen/dish_server.py --provider gemini
```

- 使うモデルは `OPENAI_IMAGE_MODEL`（既定 `gpt-image-2`。使えないアカウントなら `gpt-image-1`）
- 画質は `OPENAI_IMAGE_QUALITY`（`low` / `medium` / `high`、既定 `medium`）。速さと料金で決める
- 元の皿の形をなるべく残すため `input_fidelity: high` を付けて頼む。モデルが対応していなければ、外して頼み直す
- 写真は横長（1536 × 1024）で頼む
- 画面は 45 秒待つ。過ぎたら用意した写真を出す（`index.html?dishwait=30` で変えられる）
- 画面は `http://localhost:9001/dish` に送る。別の PC で動かすときは `index.html?dish=http://<PC>:9001/dish`
- 作った写真と指示は `screen/generated/` に保存する（git に入れない）
- 1 日に作る枚数の上限は `DISH_MAX`（既定 400 枚）。お金の上限の代わり
- 費用の目安（2026 年の記事での値。OpenAI の公式の料金表で確かめる）: GPT Image 2 の 1024 × 1024 で 低 約 0.006 ドル・中 約 0.05 ドル・高 約 0.21 ドル。送る皿の画像の分が別にかかる。来場者 200 人を「中」で作ると 10 ドル前後
- 待ち時間は数秒〜30 秒くらいと書かれている。展示用 PC と会場のネットで `--test` を何回か動かして測る。長ければ `low` にする

切っていないにんじんを出したときは「切っていない丸ごとのにんじん、葉付き」、葉の付いた端のピースがあるときはそれも書いて頼む。「足したり切ったりしない」とも書く。

用意した写真（生成できないときの予備）

| 名前 | 写真 | 出すとき |
| --- | --- | --- |
| `good` | にんじんのグラッセ | `comment` が `good` |
| `burnt` | こげたにんじん | `comment` が `overcooked` か `burnt` |
| `undercooked` | 生焼けのにんじん | `comment` が `undercooked` |
| `salty` | しょっぱいにんじん | `comment` が `too_salty` |

- `dishes/` の `*.jpg` は皿の縁で切り出したもの、`dishes.js` はそれをページに埋め込んだもの。元の画像（`*_raw.png`）は git に入れない
- 写真は画像生成 AI（Z Image）で作った試作

## 操作パネル（右下）

サーバーの代わりにイベントを送れる。キーでも送れる。

| キー | イベント |
| --- | --- |
| K | 振り下ろす |
| C | 切る（ピースを 1 つ増やす） |
| A | フライパンへ入れる |
| S / P | 塩 / こしょう |
| 0〜3 | 火（切・弱・中・強） |
| Enter | 提供（点数はデモ用の仮の計算） |
| R | リセット |
| D | デモの再生・停止 |

「料理の写真を試す」のボタンで、4 枚の写真をそれぞれ出して確かめられる。「マウスで包丁を動かす」をオンにすると、マウスで包丁を動かせ、クリックで振り下ろせる。「音を出す」で効果音が鳴る。

## 確認用の指定

- `?t=13` … デモを 13 秒の所まで早送りして表示する
- `?t=13&hold` … 13 秒の所で止める（スクリーンショット用）
- `?panel=0` … 操作パネルのボタンを隠す（展示用）
- `?gen=1` … 「料理の写真を画像生成で作る」をオンにして開く
- `?t=27&gen=1&after=1` … 提供の直後まで早送りし、画像生成の返事を待ってから 1 秒進めて止める

## まだ入っていないもの

- 3DGS の背景（撮影データができたら、受け渡し口の向こうの絵と置き換える）
- にんじん以外の野菜、電子レンジの加熱、フライパンの傾き
- 本番のおもちゃの包丁の大きさ（`KNIFE_S`）と、まな板座標の向き（`V_FROM_FRONT`）。キャリブレーションを決めたら合わせる
- 会場でネットが切れても動くように、three.js をこのフォルダーに置いて読み込む形にする
